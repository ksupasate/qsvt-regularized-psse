## Overview

This repository provides a reproducible implementation and benchmark evaluation
of QSVT-compatible regularized spectral filtering for power-system state
estimation. It studies controlled synthetic systems and IEEE/PYPOWER benchmark
network models, compares regularized classical estimators, and evaluates QSVT
as a possible implementation pathway for the same spectral filter.

The artifact contains source code, fixed experiment configurations,
machine-readable evidence, validation tools, and lightweight examples. It does
not contain the paper's LaTeX sources, submission packages, or drafting history.

## Research Scope

IEEE/PYPOWER provides benchmark network models: buses, branches, generators,
network topology, electrical parameters, and operating-point information.
Measurement rows are generated by code from those models according to the
selected experiment configuration.

No PMU or SCADA field data are used. Sensor placement, covariance, missing-row
patterns, bad-data perturbations, and weak-area weights are controlled simulation
inputs rather than field-calibrated statistics.

QSVT is studied as an implementation pathway for a regularized spectral filter.
No quantum speedup or quantum advantage is claimed. Ridge/Tikhonov and the exact
QSVT target are numerically equivalent in the classical simulator when the
matrix, right-hand side, and regularization parameter `alpha` are identical.
Polynomial, phase-response, circuit, and finite-shot errors are reported
separately from that exact-target identity.

See [Claim Scope](docs/CLAIM_SCOPE.md) and
[Measurement Model](docs/MEASUREMENT_MODEL.md) for the full interpretation
boundary.

## Method Summary

For a weighted linearized measurement system

\[
\widetilde H\,\Delta x \approx \widetilde r,
\qquad
\widetilde H=R^{-1/2}H,
\qquad
R_{ii}=\sigma_i^2,
\]

the Ridge/Tikhonov estimator applies the singular-value filter

\[
f_\alpha(\sigma)=\frac{\sigma}{\sigma^2+\alpha}.
\]

Regularization limits amplification associated with small singular values. The
software measures conditioning, estimator error, robustness under controlled
perturbations, and the accuracy or feasibility of QSVT-compatible polynomial
and circuit realizations within explicitly declared scales.

## Installation

Python 3.11 or newer is required. CPython 3.12 matches the recorded artifact
environment most closely. No GPU or quantum hardware is required.

Clone the repository, enter its root, and use either Conda or a virtual
environment. The editable install exposes the `robust_qsvt_se` package directly
from `src/`.

## Environment Setup

Recommended Conda setup:

```bash
conda env create -f environment.yml
conda activate qsvt-se
```

Pip-only alternative:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -e . --no-deps
```

On Windows PowerShell, activate with `.venv\Scripts\Activate.ps1`. Direct
publication dependencies are pinned; platform BLAS/LAPACK implementations may
still produce small floating-point or timing differences.

## Quick Start

Run the lightweight end-to-end workflow:

```bash
bash scripts/reproduce_all.sh
```

It checks the Python environment, runs the repository validator, executes the
deterministic IEEE14 quickstart, and lists the generated example artifacts. It
does not launch paper-scale sweeps or overwrite canonical evidence.

For only the five-case smoke suite:

```bash
python scripts/run_smoke_test.py
```

Expected runtime is seconds to a few minutes on a laptop-class CPU. Outputs are
written under `outputs/examples/`; each command prints its actual runtime and
output location.

## Reproducing Experiments

The public dispatcher redirects reruns to `outputs/generated/<run-id>` unless
`--output-dir` is supplied. It does not overwrite the output directory declared
inside a canonical config.

Synthetic conditioning:

```bash
python scripts/run_experiment.py --config configs/ieee14_synthetic_sweeps.yaml
```

DC- and AC-linearized IEEE14 examples:

```bash
python scripts/run_experiment.py --config configs/ieee14_dc_smoke.yaml
python scripts/run_experiment.py --config configs/ieee14_ac_smoke.yaml
```

PYPOWER AC-linearized cases:

```bash
python scripts/run_experiment.py --config configs/real_ieee14.yaml
python scripts/run_experiment.py --config configs/real_ieee30.yaml
python scripts/run_experiment.py --config configs/real_ieee57.yaml
python scripts/run_experiment.py --config configs/real_ieee118.yaml
python scripts/run_experiment.py --config configs/real_ieee300.yaml
```

Nonlinear AC cases use `configs/nonlinear_ac_ieee*_seed10.yaml`. IEEE118 and
IEEE300 runs can be long-running; IEEE300 supports `--resume`. These commands
regenerate scientific campaigns and are intentionally not called by
`reproduce_all.sh`.

The complete registered subset, including model type, seed provenance,
estimators, metrics, and expected output path, is in
[`experiment_manifest.json`](outputs/reproducibility_audit/experiment_manifest.json).

## QSVT Validation

Scalar target, polynomial, and phase-response validation:

```bash
python scripts/run_experiment.py --config configs/qsvt_phase_validation_paper.yaml
```

Small selected-block circuit scaling:

```bash
python scripts/run_experiment.py --config configs/qsvt_circuit_scaling.yaml
```

Full IEEE matrix resource proxies:

```bash
python scripts/run_experiment.py --config configs/qsvt_resource_full_ieee.yaml
```

The first command validates a bounded scalar response. The second executes small
configured constructions or records structured infeasibility. The third reports
resource proxies. None performs full IEEE-scale quantum-hardware execution.

## Configuration Guide

[`configs/README.md`](configs/README.md) indexes the established configuration
layout by synthetic, IEEE14/30/57/118/300, robustness, nonlinear, and QSVT
families. Random seeds, missing-data rules, estimator parameters, phase methods,
and output identifiers are part of the configuration provenance.

Use `--output-dir` to select a rerun destination. Do not edit a canonical config
only to change where files are written.

## Expected Outputs

Standard single runs produce a resolved config, `metrics.csv`, estimator JSON,
singular values, and a run log. Sweeps produce trial-level
`aggregate_metrics.csv`, grouped `summary_metrics.csv`, and checkpoint/progress
records where supported. QSVT runs add phase-response, circuit-scaling, or
resource-estimate tables appropriate to the selected configuration.

Generated example and rerun outputs belong under:

```text
outputs/examples/
outputs/generated/
```

A fresh clone versions the 41 `outputs/` roots that the test suite and the
reproduction validator read, so both pass on a bare checkout with no downloads.
Any other `outputs/...` path named in the documentation is a *destination* that
a run creates, not a file shipped in Git. See
[`RESULTS_INDEX.md`](RESULTS_INDEX.md#which-output-paths-are-in-a-git-checkout)
for the exact list.

Required schemas are documented in
[`examples/expected_outputs/README.md`](examples/expected_outputs/README.md) and
checked with:

```bash
python scripts/validate_outputs.py
```

## Known Limitations

- No real utility PMU/SCADA measurements or field-calibrated sensor statistics
  are included.
- Missing measurements and bad data are controlled simulation perturbations.
- QSVT results establish scoped filter-implementation feasibility or boundaries,
  not end-to-end quantum advantage.
- Large IEEE cases use classical spectral calculations and resource models;
  application-scale quantum hardware is not executed.
- Runtime depends on platform, BLAS/LAPACK, optimizer, and simulator versions.
- Raw campaigns can require substantial CPU time, memory, and external storage;
  the one-command workflow intentionally runs only lightweight checks.
- The six raw datasets in `data_manifest.json` are required for complete
  evidence-level reproduction. Their archive DOI is reserved
  (`10.5281/zenodo.22326883`), but the Zenodo record is still an
  unpublished draft, so no retrieval URL exists yet and the files are not
  publicly downloadable. Lightweight validation and the included compact
  artifacts do not require those downloads.

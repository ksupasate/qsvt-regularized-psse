## The one substantive defect found and fixed

The exact-tree suite passed, but that was not sufficient evidence that the
published repository works. The staging directory held `outputs/` evidence that
`.gitignore` would have excluded from the commit, so tests were reading files
that would never reach a clone.

Materializing only the tracked files and running the suite there exposed it:

| Clean-clone check | Before | After |
|---|---:|---:|
| pytest failures | 181 | **0** |
| pytest errors | 97 | **0** |
| affected test files | 77 | **0** |
| validator failures | 19 | **0** |
| tracked files | 1,238 | 1,556 |
| tracked size | 11.1 MiB | 114.4 MiB |

Three separate symptoms, one cause. The fix was to narrow the `outputs/**`
exclusion so the repository versions exactly the evidence its own checks read:
41 `outputs/` roots, the QSP phase-angle caches inside them, and the five
registered smoke-test snapshots.

**No test was weakened, skipped, xfailed, or deleted to reach the passing
result, and no scientific file was modified.** The same assertions now run
against the same bytes, in a checkout that actually contains them.

The trade-off was measured before it was taken: the lean alternative (1.75 MB of
small evidence only) left 59 tests failing and would have required the three
large evidence roots to be downloaded. The maintainer chose the self-contained
artifact. Largest single tracked file is 19.4 MiB, so no GitHub limit is
approached and Git LFS is not needed.

## Two smaller defects found and fixed

1. **A dead manuscript-only script.** `scripts/export_latex_assets.py` imported
   `robust_qsvt_se.paper.latex_asset_export`, which the public boundary removes.
   It raised `ModuleNotFoundError` in the public tree. It was removed and
   recorded in the exclusion manifest. A systematic sweep then confirmed all
   2325 remaining `robust_qsvt_se` import references resolve.

2. **A frozen evidence manifest regenerated in place.** Running the suite
   rewrote `outputs/qsvt_oracle_model_resources/manifest.json` with the
   release-audit pytest command, a fresh timestamp, and `git_commit: null`.
   Three sibling files regenerated byte-identically. All four were restored from
   the curated source, so the shipped manifest carries its true provenance.

## Skips and warnings

The 32 skips are pre-existing guarded skips that report their own reason; the
two distinct reasons are an optional study output not being generated, and a
manuscript table the public repository deliberately does not ship. The 2434
warnings are entirely third-party: a Qiskit 2.3 `DeprecationWarning` for
`Gate.control(annotated=None)` and a NumPy "Mean of empty slice"
`RuntimeWarning` on an expected empty-selection branch.

The 6 validator warnings are: `conda` not on `PATH` (the documented environment
warning), plus the five intentional resolved-config omissions that replace
snapshots whose `output.root` recorded a machine-local path.

## Known non-blocking limitations

- Running `pytest` writes into a few canonical `outputs/` directories, because
  those tests default `output_dir` to the canonical path. After a test run,
  `git status` in a fresh clone shows modifications a user should discard. This
  is pre-existing suite behavior, not introduced by the release.
- 308 cosmetic Ruff findings remain repo-wide (243 `E501`, 20 `E402`, 18 `I001`,
  16 `RUF046`, and a handful of others), concentrated in `scripts/`. No
  release-facing entry point is affected and no correctness rule fires.
- Three generic `/tmp/...` scratch destinations are hardcoded in non-entry-point
  code, which is a portability wart on Windows.
- The six raw datasets in `data_manifest.json` still require the external
  archive for complete evidence-level reproduction. They are **not** needed to
  run the test suite, the validator, or the quickstart.

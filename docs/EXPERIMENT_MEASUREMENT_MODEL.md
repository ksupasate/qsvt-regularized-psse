# Experiment Measurement Model

## 1. Overview

This repository evaluates controlled state-estimation systems generated from
benchmark network models and synthetic weighted matrices. The code is designed
for reproducible algorithmic comparison, not field-data validation.

The main distinction is:

- Nonlinear AC experiments perturb raw generated measurements.
- Single-step synthetic, DC, and AC-linearized experiments perturb an already
  weighted residual vector.

## 2. What IEEE/PYPOWER Cases Provide

IEEE/PYPOWER cases provide static benchmark network data: buses, branches,
admittance parameters, voltage magnitudes, voltage angles, and case metadata.
The repository uses these data to generate measurement equations and Jacobians.

## 3. What IEEE/PYPOWER Cases Do Not Provide

IEEE/PYPOWER cases do not provide real PMU/SCADA field measurement streams,
utility sensor placement records, real sensor covariance matrices, or field
bad-data events. Measurement rows are generated by repository code.

## 4. Measurement Types by Experiment Group

- Synthetic: `synthetic_weighted_row`.
- DC-linearized: branch-flow, bus-injection, and configured angle rows.
- AC-linearized: voltage magnitude, active/reactive injection, and
  active/reactive branch-flow rows.
- Nonlinear AC: the same AC measurement functions are used to generate raw
  measurement vectors and per-iteration Jacobians.
- QSVT matrix/resource paths: weighted AC Jacobian rows used as diagnostic
  matrix rows.

## 5. Nonlinear AC Workflow

Nonlinear AC experiments build a raw measurement vector:

```text
z = h(x_true) + e + b
```

Here `h(x_true)` is generated from the AC measurement equations, `e` is
zero-mean Gaussian noise, and `b` is sparse signed additive bad data when
enabled. Each iteration then forms a weighted linear update system from
`z - h(x_k)` and the Jacobian at `x_k`.

## 6. Single-Step / Linearized Workflow

Single-step experiments solve one already weighted linearized problem. The
perturbation is:

```text
r_tilde_perturbed = r_tilde_clean + e_tilde + b_tilde
```

This applies to synthetic, DC-linearized, and AC-linearized single-step paths.
It is not the same as perturbing a raw nonlinear `z` vector.

## 7. Synthetic Workflow

Synthetic systems generate `H_tilde` directly by a controlled SVD construction
with a target condition number. The right-hand side is `r_tilde = H_tilde
x_true`. These rows are abstract weighted rows and have no bus, branch, PMU, or
SCADA sensor placement semantics.

## 8. DC-Linearized Workflow

DC systems generate an unweighted measurement matrix `H` from branch-flow,
bus-injection, and configured angle rows. A synthetic angle vector creates
`z = H theta_true`. Rows are divided by configured standard deviations to obtain
`H_tilde` and `r_tilde`.

## 9. AC-Linearized Workflow

AC single-step systems evaluate AC measurement equations at `x_true` and at a
perturbed linearization point `x0`. The residual `z_true - z0` and the Jacobian
at `x0` are divided rowwise by configured standard deviations. RMSE in this
workflow is update-vector RMSE against `x_true - x0`.

## 10. Perturbation Implementation

Noise is additive zero-mean Gaussian using seeded NumPy `default_rng`.
Single-step noise is added to `r_tilde`. Nonlinear AC noise is added to raw
`z_true` before missing-row selection and bad-data insertion.

## 11. Missing-Measurement Implementation

Missing measurements are random row drops. Single-step paths remove rows from
`H_tilde`, `r_tilde`, and row metadata. Nonlinear AC removes raw measurement
rows and keeps the same row indices for per-iteration Jacobians.

## 12. Bad-Data Implementation

Bad data is sparse, signed, additive, and applied after missing-row selection.
Single-step bad data is added directly to `r_tilde`. Nonlinear AC bad data is
added to raw `z` and scaled by the row measurement standard deviation.

## 13. Implicit Diagonal R and Weighting

The code does not materialize a dense covariance matrix. The diagonal covariance
is implicit:

```text
R_ii = sigma_i^2
```

Weighted rows are formed by:

```text
H_tilde[i, :] = H[i, :] / sigma_i
r_tilde[i] = r[i] / sigma_i
```

## 14. Condition-Number Computation

The main condition number is computed from the weighted matrix:

```text
kappa(H_tilde) = sigma_max(H_tilde) / sigma_min(H_tilde)
```

Normal-equation WLS may additionally report gain-matrix conditioning, but that
is separate from the main `cond(H_tilde)` metric.

## 15. RMSE Computation

RMSE compares an estimate to the stored reference vector:

```text
RMSE = sqrt((1 / n) * sum_i (x_hat_i - x_true_i)^2)
```

For AC single-step runs, `x_true` is the true update vector. For nonlinear AC
runs, `x_true` is the full AC state vector.

## 16. Claim Boundaries

This repository supports controlled benchmark and feasibility claims. It does
not provide PMU/SCADA field-data validation, full IEEE-scale quantum hardware
execution, or quantum speedup evidence.

The classical `qsvt_regularized` simulator implements the same regularized
spectral target as ridge/Tikhonov when the same `alpha` is used. It should not
be described as numerically beating ridge in the classical simulator.

## 17. Limitations

- Measurement placement is generated from code-level inclusion rules, not
  utility deployment records.
- Stress parameters are controlled assumptions and are not field calibrated.
- Missing measurements use random row removal only.
- Weak-area stress is implemented through standard-deviation multipliers and
  bad-data eligibility, not a full observability-planning model.
- QSVT circuit and phase results are implementation-pathway evidence, not full
  hardware execution.

## 18. Recommended Professor-Facing Explanation

The experiments use benchmark IEEE/PYPOWER network models to generate
auditable synthetic measurement systems. For nonlinear AC experiments, the code
perturbs raw measurements as `z = h(x_true) + e + b`. For synthetic, DC, and
AC-linearized single-step experiments, the code perturbs the already weighted
residual `r_tilde`. The covariance model is diagonal and implicit through
configured standard deviations, so row weighting is division by `sigma_i`.
Results support controlled robustness and feasibility claims, not field-data
validation or quantum speedup.
